## Что нужно сделать в этой итерации

### 1. Превратить лендинг в мини-сайт с админкой

Архитектура (рекомендуемая, всё в уже существующем аккаунте Cloudflare, бесплатные тарифы):

- Фронт: **Astro** (статика + SSR через `@astrojs/cloudflare`) на **Cloudflare Pages**, контент из **D1**, файлы в **R2**. Пока DNS avocado.rest указывает на GitHub Pages — сначала собрать и проверить на `*.pages.dev`, затем перенести домен (CNAME у регистратора → Cloudflare Pages, либо перенос DNS в Cloudflare). До переноса GitHub Pages остаётся рабочим.
- Альтернатива, если Astro избыточен: оставить статический сайт, генерировать страницы GitHub Actions из D1 по вебхуку из админки.
- Админка `/admin`: вход владельца (пароль + сессия в cookie, либо Cloudflare Access), разделы: страницы, товары/услуги (категории, страны, наличие, «скоро», цена или «по запросу»), новости, заявки из чата (список сессий из D1 воркера, история, ответ через того же бота), настройки (контакты, кошельки для оплаты).
- Страницы сайта: главная (обновлённый hero и продукты), **Hass**, **Ettinger**, **Аренда панели** (1/3/12 месяцев, цена по запросу), каталог: **Домены**, **VPS**, **Выделенные серверы**, **Bulletproof-хостинг** (метка «скоро»), **Прокси**; **Страны** (карта/список локаций); **Оплата** (любая криптовалюта, без KYC и верификаций — описать процесс: заявка → счёт → оплата → выдача); **Новости**; **Контакты**.
- Новости из Telegram-канала: добавить бота @avogurubot администратором канала владельца, в `setWebhook` включить `channel_post`/`edited_channel_post`, сохранять посты (текст, фото через R2, дата, ссылка `t.me/<канал>/<id>`) в D1, показывать на `/news` с пагинацией; в админке — скрыть/закрепить/отредактировать; ручные новости тоже.
- Чат-виджет и бот сохранить как есть; воркер расширить (news import, admin API) или объединить с Pages Functions — но контракт `/api/chat/...` не ломать.

### 2. Апгрейд дизайна — «реалистичнее и дороже»

- Больше фотореализма в том же стиле: для каждой категории каталога — свой рендер (домены, VPS, dedicated, прокси, страны) по промтам в стиле существующих (см. `assets/renders/*.prompt.txt`). Генерирует владелец во внешнем ИИ по твоим промтам: выдай ему ТЗ (размеры, композиция, тёмный верх для текста, без текста на картинках), файлы придут в `assets/renders/`, ты конвертируешь в WebP с мобильными вариантами (Pillow).
- Использовать `assets/img/avocado-cutout.webp` (плод без фона) для OG-картинки и акцентов.
- Держать палитру и типографику из MASTER.md, обновить документ по итогам. Стеклянные панели, мягкие свечения, никакого «киберпанка».
- Микроанимации только на opacity/transform, reduced-motion учитывать.

### 3. Оплата криптовалютой без KYC

- Первый этап: заявка через чат/бота → в админке создаётся счёт с суммой и адресом кошелька нужной сети (кошельки задаются в настройках админки: BTC, ETH, USDT TRC-20/ERC-20, XMR, LTC и др.) → владелец подтверждает оплату вручную → выдача. Никаких сторонних процессоров без согласования.
- Второй этап (обсудить с владельцем): self-hosted BTCPay Server на VPS для автоматического подтверждения.

### 4. Порядок работы и критерии готовности

1. Прочитать README.md, MASTER.md, worker/src/index.js, index.html. Составить план и краткую смету по шагам, начать с каркаса мини-сайта и админки.
2. Каждую страницу проверять скриншотами 1440/390, Playwright-тесты обновлять и держать зелёными; `node --check` на JS.
3. Коммиты небольшие, сообщения по делу; секреты — только в Cloudflare/gitignored.
4. Готово, когда: сайт открывается по avocado.rest с новыми страницами; админка защищена и управляет контентом; новости тянутся из канала; чат и бот работают как раньше; Lighthouse Performance/Accessibility ≥ 90 на мобильном.
