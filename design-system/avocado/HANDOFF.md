# Передача проекта avocado.rest новому ИИ

Состояние проверено 12 сентября 2026 года. Это передача завершённой работы,
а не поручение немедленно реализовать весь список будущих задач.
Перед изменениями прочитайте этот файл, `README.md`, `site/README.md` и
`design-system/avocado/MASTER.md`, затем проверьте текущие Git и deployment.
Новые инструкции владельца имеют приоритет над этим снимком состояния.

## Результат последней задачи

На **https://avocado.rest** опубликован полноценный многостраничный сайт.
Последний запрос — сделать понятную витрину хостинга: цены, флаги стран,
характеристики, подбор домена и удобный заказ. Эта переработка завершена,
проверена и выложена. Незакоммиченных изменений перед подготовкой передачи не было.

- Главная: анонимный хостинг → четыре направления с ценами → домен → четыре
  выбранных тарифа VPS → страны → собственные Hass/Ettinger → процесс заказа
  и криптооплаты → FAQ → подвал.
- Каталог: VPS, выделенные серверы, домены, прокси, Bulletproof со статусом «скоро».
  Есть отдельные страницы тарифов, CPU/RAM/диск/порт, валюта, период и условия.
- Фильтры страны, памяти и валюты работают на статике. Состояние в hash:
  `/catalog/vps/#country=FI`, а не в серверном query-параметре.
- Страны показывают только услуги, для которых эта география есть в каталоге.
- «Заказать» открывает окно с выбранным тарифом, страной, пожеланием к ОС
  и комментарием. Кнопка «Продолжить в чате» добавляет заявку к черновику,
  сохраняя уже написанный текст. Сообщение отправляет сам клиент.
- Подбор домена проверяет синтаксис, поддерживает кириллицу/IDN и цену зоны.
  Прямой заказ зоны также запрашивает имя. Это **не автоматическая проверка
  доступности и не регистрация**: оператор подтверждает имя и стоимость до счёта.
- Страницы ПО, аренды, оплаты, новостей и контактов сохраняются.

## Решения владельца, которые нельзя перепутать с ранним ТЗ

1. **Домен остаётся на GitHub Pages. Владелец отказался переносить DNS/хостинг.**
   Ранний план переноса публичного сайта на Cloudflare Pages отменён.
2. Последнее позиционирование — **анонимный хостер с собственными решениями ПО**.
   Более раннее требование «разработчики ПО прежде всего» изменено владельцем.
   Hass и Ettinger остаются важными продуктами, но следуют за предложением хостинга.
3. Все услуги продаются от имени Avocado. Имена поставщиков, ссылки на них,
   внутренние цены закупки и будущие подключения не показываются посетителю
   и не публикуются в Git. Для них есть закрытые данные, описанные ниже.
4. Интеграции поставщиков пока не делать: разрешено использовать данные для
   временного прайса, сами API покупки/выдачи не подключались.
5. Админка защищена и **не имеет публичной ссылки** в меню, подвале или sitemap.
   Владелец получил временный пароль ранее и намеревался сменить его сам.
   Не сбрасывайте пароль и не генерируйте новые секреты без необходимости.
6. Русский копирайт, sentence case, только SVG-иконки, видимый фокус,
   контраст 4.5:1, тапы от 44 px, проверки 1440/390.
7. Коммерческие действия ведут к заявке в существующем чате; навигационные
   ссылки открывают страницы. Не заменять чат внешней формой.
8. Работать автономно, писать по-русски кратко. Спрашивать только действительно
   недостающие доступы, деньги и утверждённые юридические формулировки.

Cloudflare Pages рендерит актуальный контент D1 и обслуживает админку.
`site/scripts/export-github-pages.mjs` читает `/api/public/manifest`, экспортирует
только опубликованные страницы и публичные ресурсы в `site/github-dist/`.
GitHub Actions публикует этот каталог. Важное следствие: правка D1 не появляется
на основном домене до следующей успешной публикации.

Workflow `.github/workflows/publish-site.yml`: push в `main`, ручной запуск,
расписание на 7-й, 22-й, 37-й и 52-й минуте UTC. Расписание может задерживаться.
Дополнительные секреты Actions не нужны. Новости `/news?page=N` при экспорте
получают статические адреса `/news/page/N/`. Админка и серверные API не экспортируются.

**Корневой `index.html` — исторический лендинг для отката.** Изменение только
этого файла не обновит нынешний сайт. Production-шаблоны находятся в `site/src/`.
`_config.yml` относится к запасному режиму Jekyll; текущая публикация идёт через Actions.

Эти файлы gitignored. Токен уже был предоставлен и использован: не просите его
повторно без проверки доступности через существующий release-helper.
OAuth-вход Cloudflare с сервера не работал; используется API token.
Не выводите содержимое env-файлов в логи и не вставляйте значения в команды,
документацию, сообщения, коммиты или frontend. Перед commit/deploy запускайте
существующий скан известных секретов. В этой передаче значений секретов нет.

## Каталог, оплата и новости: что действительно включено

31 тариф с ценой: 12 VPS, 6 выделенных серверов, 8 доменных зон, 5 предложений
прокси. Дополнительно сохранены 5 общих карточек категорий. Есть 17 стран,
но VPS — только FI, NL, SE, IS, CH и US; география прокси шире.
По умолчанию наличие подтверждается оператором, а цены ориентировочные.
Не превращать отсутствие сведений в выдуманные характеристики, склад или SLA.

Валюта и период обязательны. USD и EUR не сравниваются как одна валюта.
Домены — первый год, продление по запросу; часть доменных ориентиров происходит
из демонстрационного прайса и требует подтверждения перед счётом.
Прокси — за 1 IP / 30 дней; у оптового предложения есть минимальное количество.
У отдельных серверов есть минимальный срок аренды. Эти условия видны рядом с ценой.

Приватное исследование: `output/partner-research/`, привязки:
`output/procurement-sources.json`. Поля `source_name/source_url/source_checked_at`
доступны в защищённой админке. Публичный `getSiteData` удаляет их до рендера.
Не переносить приватные файлы, имена и URL из них в отслеживаемую документацию.

Первый этап оплаты: заявка → согласование → счёт в CMS с суммой, сетью и кошельком
→ перевод клиента → ручное подтверждение → выдача. Без настроенного кошелька
рабочий оплачиваемый счёт не создаётся. Автоматического криптопроцессинга нет.

Новости разрешённого канала принимаются через `channel_post/edited_channel_post`,
сохраняются в D1; доступны ручные новости, скрытие, закрепление и редактирование.
Бот был подтверждён администратором канала. На последней проверке webhook работал,
очередь была пуста. При неактивном R2 текст продолжает работать, а фотографии
ждут восстановления медиа. Подробности: `worker/NEWS.md`.
Архив канала Bot API не импортирует. Удаление поста требует ручного скрытия
новости; элементы альбома пока становятся отдельными новостями. После активации
R2 нужны bindings у Worker и Pages; cron догружает ожидающие фото без повторной
публикации поста. Не обещать более широкую синхронизацию, чем реализована.

Hass и Ettinger в этом репозитории представлены страницами и условными схемами.
Само серверное ПО этих продуктов здесь не реализовано; витрина не подтверждает
наличие готового продукта или отдельного backend, которого нет в исходниках.

## Публикация изменений

Для изменения Astro-шаблонов сначала обновить серверный рендер на Cloudflare,
затем публиковать статический экспорт на GitHub. Один push исходников без обновления
рендера Pages не заменит шаблоны публичного сайта.

Из `D:\AvocadoREST\site`:

```powershell
npm run check
npm test
npm run build
# Только если добавлены новые миграции: backup D1 + применение
node scripts/cloudflare-release.mjs migrate
node scripts/cloudflare-release.mjs site
npm run export:github
```

После проверок — небольшие коммиты, `node site/scripts/check-secrets.mjs --git`
из корня и push в `main`. Дождаться успеха workflow и проверить основной домен.
Проверки разметки/кода должны предшествовать релизу; команды выше не заменяют QA.

Release-helper читает локальные секреты и маскирует вывод. Загружается только
`site/pages-dist`, **не сырой `site/dist`**: адаптер может копировать `.dev.vars`
в промежуточные файлы. Упаковщик и secret-scan убирают приватное из артефакта.

`prepare` нужен при первоначальной настройке или изменении bindings; `worker`
и `webhook` — при соответствующих изменениях бота. Для обычной правки витрины
перезапускать их не требуется. Не выполнять все release-команды автоматически.

## Локальный запуск и проверки

См. `site/README.md`, `worker/tests/README.md`. Из `site/`: `npm run build`,
затем `npm run dev:stack`. Предварительно запустить `node scripts/mock-telegram.mjs`
из `worker/`. Сайт 4322, локальный чат 4331, mock Telegram 8099; общая тестовая
D1/R2 находится в игнорируемом `output/qa-stack/`.
Статический экспорт смотрится через `node scripts/preview-github.mjs` на 8000.

На Windows завершать собственный родительский Node runtime, чтобы workerd
отпустил SQLite. Не удалять `.wrangler/state` и не завершать чужие процессы.
Созданные в последней работе серверы 4322/4331/8099/8000 остановлены;
прежний Worker на 8787 был оставлен работающим. PID перепроверять, не брать из истории.

Основные команды из `site/`:

```powershell
$env:UI_BASE_URL = 'http://127.0.0.1:4322'
node tests/site-ui.cjs
node tests/order-ui.cjs
node tests/catalog-ui.cjs http://127.0.0.1:4322
node scripts/github-smoke.mjs --base https://avocado.rest
```

`site-ui.cjs` поддерживает `UI_ROUTES`, `UI_OUTPUT_DIR`, `UI_SKIP_CHAT`.
Указывайте видимую CTA (`[data-chat]:visible`), поскольку в пустом состоянии
фильтров есть скрытая кнопка помощи. `order-ui.cjs` перехватывает chat API;
реальных тестовых сообщений в рабочие чат/Telegram не отправлять.
`node scripts/production-smoke.mjs --base https://avocado-rest.pages.dev --admin`
проверяет вход/чтение/выход без изменения контента. Секреты не печатает.
Lighthouse запускать отдельно от других браузерных тестов.
