# Переход avocado.rest на мини-сайт

## Состояние на 12.09.2026

Рабочий preview: https://avocado-rest.pages.dev, админка: `/admin`.
Деплой Pages `01cfb0f2`; версия чат-воркера `d9c58d99-d50e-47eb-9be5-64d23df09357`.
Удалённая D1 мигрирована после резервного копирования. Вход, чтение восьми
разделов админки и отзыв сессии проверены на Pages; 15 публичных маршрутов,
404, прежний API чата и Telegram webhook прошли smoke.
Пароль находится только в игнорируемом `site/output/production-access.json`.

`avocado.rest` пока обслуживается GitHub Pages: R2 не включён, токен не видит
DNS-зону. Перенос домена не выполнен. Не получены новые рендеры категорий,
подтверждённые страны/наличие, кошельки и юридические тексты.

## Порядок работ

1. Изолировать Astro-приложение в site/. Исходный GitHub Pages остаётся рабочим до переключения домена.
2. Добавить SSR страницы, общие компоненты и доступную мобильную навигацию. Сохранить /api/chat/... и текущий браузерный sid.
3. D1: страницы, каталог, страны, настройки, сессии админки, счета. R2: загруженные фотографии и Telegram-медиа.
4. Защитить /admin; добавить управление контентом, ответами в чате, ручными счетами и оплатой.
5. Расширить webhook Telegram для одного настроенного канала; сохранять редактирования владельца и обработать повторы.
6. Подготовить английские промпты категорий, конвертер WebP/mobile и OG на основе avocado-cutout.
7. Прогнать API/auth/CRUD/payment/news тесты, браузерные сценарии и скриншоты каждой страницы на 1440/390; Lighthouse mobile Performance/Accessibility >=90.
8. Создать Cloudflare Pages preview, D1/R2 bindings и секреты; выполнить миграции и smoke-check. Затем перенести avocado.rest и проверить production.

## Решения

- Astro 7.3.2 + @astrojs/cloudflare 14.3.1. Адаптер выпускает Workers build; собственный `site/scripts/package-pages.mjs` упаковывает его ES-модули в Cloudflare Pages advanced mode. Совместимость проверена в настоящем workerd. При обновлении адаптера нужно повторить проверки. Старые версии Astro/адаптера не использованы из-за известных уязвимостей.
- Публикуется только `site/pages-dist/`. Скрытые файлы и серверный wrangler.json исключаются; сборка блокируется при обнаружении известных секретов. Pages-конфиг вынесен в `pages/`, чтобы избежать автоматической подмены конфигом Workers.
- Общая D1 avocado-chat сохраняет существующие sessions/messages. CMS использует отдельные таблицы; миграции только добавляют данные/схему.
- Pages обращается к чату через service binding; путь /api/chat/... сохраняется. Внутренние ответы оператора защищены отдельным секретом.
- В каталог не добавляются выдуманные цены, страны и наличие. Неподтверждённые данные — черновики или «по запросу». Bulletproof — «скоро».
- Кошельки не выдумываются. Счёт фиксирует актив, сеть и адрес на момент создания; оплату и выдачу подтверждает владелец.
- BTCPay Server — отдельный второй этап после выбора VPS и согласования расходов.

## Внешние зависимости

- Токен сохранён в игнорируемом worker/.dev.vars.prod. Доступ к Pages/D1/Workers подтверждён; создан проект avocado-rest. Перед миграциями сохранена локальная резервная копия удалённой D1.
- R2 в аккаунте пока не активирован: Cloudflare возвращает 10042. Владелец включает R2 в Dashboard (может потребоваться платёжный профиль); после этого повторяются prepare/worker/site. Pending media догружаются cron.
- Канал @avocadodev (-1004361494715), бот @avogurubot — администратор. Импортируются новые посты и редактирования после настройки webhook; Telegram Bot API не предоставляет историю старых публикаций.
- Токен не видит зону avocado.rest. Текущие NS: adam.ns.cloudflare.com и nola.ns.cloudflare.com. Нужен доступ к этой зоне либо изменение DNS владельцем.
- Нужны подтверждённые страны, наличие, кошельки с сетями и юридические тексты.
- Новые рендеры владелец генерирует по подготовленным промптам и кладёт в assets/renders/.

## Критерии приёмки

Production-домен открывает новый сайт; защищённая админка действительно сохраняет в D1; импортируются посты разрешённого канала; чат/бот работают без изменения контракта; мобильные Performance и Accessibility >=90. Локальные проверки и preview не считаются выполнением production-критериев.

## Переключение домена

Порядок привязки: [Cloudflare Pages custom domains](https://developers.cloudflare.com/pages/configuration/custom-domains/).

1. Проверить avocado-rest.pages.dev: все публичные маршруты, вход и восемь разделов CMS, `/api/health` чат-воркера и набор allowed_updates webhook. Утвердить данные каталога, кошельки и условия.
2. В Pages → avocado-rest → Custom domains добавить avocado.rest. Сначала сохранить текущие DNS-записи для отката. При доступной зоне Cloudflare связывает домен с Pages; целевой CNAME — avocado-rest.pages.dev (на apex работает flattening).
3. Добавить www.avocado.rest при необходимости, направить на Pages и настроить единственный канонический адрес. Не менять MX/TXT и другие сервисные записи.
4. Дождаться активного сертификата, проверить HTTPS, deep links, 404, чат и cookie админки на домене. Повторить mobile Lighthouse на production.
5. Пока переключение не подтверждено, GitHub Pages и файл CNAME остаются как источник отката. При проблеме вернуть сохранённые записи. База чата сохраняется общей.

## BTCPay, второй этап

После подтверждения VPS, домена, поддерживаемых монет и бюджета: отдельный BTCPay,
резервные копии и обновления, проверяемые webhook для счетов, повторная доставка
без дублей, ручное разрешение исключений. До этого действует только ручное
подтверждение владельцем; внешних платёжных процессоров нет.
